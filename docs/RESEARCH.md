# 研究計画（草案）

状態：**草案**（2026-10-17）。教授との議論で確定させる。確定したら「状態」を更新し、変更点を [DECISIONS.md](DECISIONS.md) に記録する。

## 1. 研究の問い

### 中心となる問い

> 家庭内 IoT 機器のセキュリティリスクのうち、ネットワーク通信をパッシブに観測するだけで、どれが**観測でき**、どれが**推定にとどまり**、どれが**観測できない**のか。その境界は、暗号化の普及（TLS 1.3、ECH、QUIC）やキャプチャ位置（ゲートウェイの LAN 側か WAN 側か、Wi-Fi 内部の通信を含むか）によって、どう変わるのか。

### 下位の問い

| ID | 問い | 主に答える成果 |
|---|---|---|
| RQ1 | リスクの種類ごとに、パッシブ観測で検出・推定できる範囲はどこまでか | 可観測性マトリクス（§4） |
| RQ2 | 根拠の種類（観測事実／推定／外部 DB との照合）を区別して示すと、検出結果の信頼性の評価に役立つか。何に役立つのか | `basis` の内訳と、根拠の種類ごとの適合率 |
| RQ3 | 既存の NSM／IDS（Zeek、Suricata）と比べて、機器単位の帰属と相関は何を上乗せするか | 既存ツールとの比較実験 |
| RQ4 | 同じ機器の時系列比較（ベースラインからの逸脱）で、どのような変化をどの程度の誤検知で捉えられるか | UNSW の 20 日分の連続データでの評価 |
| RQ5 | 実環境で、観測範囲（パケット欠落、Wi-Fi 内部の通信の取りこぼし）はどの程度か | 実機テストベッド（Phase 3） |

### 補助的な検証：測定装置の妥当性

研究の中心は §1 の問いに置く。そのうえで、結論が Quarant の読み違いの産物でないことを、補助的に示す。

- **検証すること**：Quarant のパーサの解釈は、標準的な実装（`crypto/tls` など）や機器の実際の解釈と、どこまで一致するか。
- **方法**：差分ファジングと、実データでの突き合わせ（E2）。TCP の並べ替えと再送への頑健さも調べる。
- **位置づけ**：計測研究で必要な「測定器の妥当性の確認」にあたる。ずれが見つかった場合は、すり抜け（evasion）の余地として可観測性マトリクスの「見えなくなる条件」に反映する。主な貢献としては主張しない。

## 2. 想定する貢献（新規性は関連研究との比較で検証する）

断定はしない。どれも §3 の比較で確かめる。

1. **根拠を区別する設計と、その評価**
   - すべての検出結果を `observed`／`inferred`／`reference_match` に分け、不確実性と限界を明示する。
   - 根拠の種類ごとに精度を実測する。例：知識 DB との照合は、宛先から推定した機器の素性に引きずられやすい（E1 で、Echo が Hue と取り違えられた事例）。
2. **可観測性の体系的な整理**
   - 「検出できたこと」だけでなく、「原理的に見えないこと」と「条件しだいで見えなくなること」を、公開データと実機データの根拠つきで示す。
3. **機器単位の帰属と相関**
   - 複数の情報源（独自エンジン、IDS、ゲートウェイのログ、脅威情報）を、機器ごとの「状況」として統合する。冗長性の削減と、正解の取りこぼしを定量化する。
4. **再現可能な評価基盤**
   - 正解ラベルつきの合成シナリオ、公開データセット 3 種での評価器、ホールドアウトによる誤検知の測定。

## 3. 関連研究（要調査。下は出発点）

| 研究・製品 | 概要（記憶に基づく。要確認） | Quarant との違い（仮説） |
|---|---|---|
| IoT Sentinel（Miettinen et al., ICDCS 2017） | 機器のセットアップ時の通信から機器の種類を識別し、脆弱な機器を隔離する | 識別が中心。リスク全般の可観測性は扱っていない |
| IoT Inspector（Princeton、Huang et al., 2020） | 利用者の PC から家庭内の IoT 通信を収集するクラウドソーシング型の研究ツール（ARP スプーフィングで通信を取得する能動的な方式。要確認） | 収集方式が能動的。Quarant はゲートウェイでのパッシブ観測と、根拠の区別を重視する |
| Mon(IoT)r（Ren et al., IMC 2019） | 81 台の IoT 機器について、情報の露出、通信先、暗号化の有無を測定した | 計測研究。監視システムではなく、根拠の種類も区別していない |
| YourThings（Alrawi et al., S&P 2019） | 家庭 IoT のセキュリティ評価の SoK。能動的な検査を含む | 能動検査を含む。パッシブ観測の範囲との比較対象として使える |
| HomeSnitch など | 暗号化された通信から機器の振る舞いを推定する | 推定の手法。可観測性の境界を示す材料になる |
| Ptacek & Newsham (1998), "Insertion, Evasion, and Denial of Service: Eluding Network Intrusion Detection" | 監視装置と通信の終端で解釈がずれることを利用した IDS のすり抜け（記憶に基づく。要確認） | 測定装置の妥当性検証（補助）の出発点 |
| Zeek / Suricata | 汎用の NSM／IDS | 機器単位の帰属、IoT 特有の判断、根拠の区別がない。比較のベースラインとして使う |
| 市販の家庭向けセキュリティ製品 | ルーター組み込み型の脅威遮断 | 判断の根拠と限界を開示しない。研究上の比較は定性的になる |

**やること**

- 各論文の手法、データ、評価指標を一次資料で確認する。
- 「パッシブ監視の限界」を扱った研究がほかにないかを調べる。
- 新規性を主張できる範囲を絞り込む。

## 4. 可観測性マトリクス（初版）

凡例

- **観測**：通信そのものに現れる
- **推定**：観測からの推論にとどまる
- **照合**：外部 DB に頼る
- **不可**：パッシブ観測では原則として見えない

「現状の根拠」の列は、その判断が何に基づくかを示す。

| リスクの種類 | 可観測性 | 見えなくなる条件 | Quarant の現状の根拠 |
|---|---|---|---|
| 機器の存在、MAC、DHCP のホスト名 | 観測 | WAN 側でのキャプチャ、ランダム化 MAC | E1-2：31/31 台を捕捉、ホスト名は 19/31 |
| ベンダー（OUI） | 照合 | ランダム化 MAC、Wi-Fi モジュールの OUI | E1-2：7/31 台はブランドと異なる |
| 機器の種類、型番 | 推定 | 暗号化（SNI と UA が見えない）、連携先クラウドとの混同 | カテゴリ推定の精度は未測定（監査の対象） |
| 平文プロトコルの使用（HTTP、Telnet、FTP、MQTT） | 観測 | なし（平文なら必ず見える） | 合成データ、E1-2（2016 年の機器で多数） |
| 認証情報の平文送信 | 観測 | TLS 化されていれば見えない | 合成データ。実データでの適合率は未測定 |
| TLS のバージョン、提示した暗号スイート | 観測 | QUIC、ECH（SNI が隠れる） | 合成データ、実 PCAP |
| 証明書の異常（自己署名、期限切れ） | 観測（TLS 1.2 以下）／不可（TLS 1.3） | TLS 1.3 では証明書が暗号化される | 実装あり。実データでの評価は未実施 |
| ファームウェアのバージョン、CVE の該当 | 照合＋推定（バージョンが平文で見える場合のみ） | ほとんどの場合、見えない | 適用可否は常に「未確認」として扱う |
| C&C 通信（執拗な再接続、周期通信） | 推定 | 少量・低頻度で TLS を使う C&C | E1-1：Mirai と Hakai は検出、Torii は見逃し |
| 外向きのスキャン | 推定（観測に近い） | なし | E1-1：Muhstik を検出 |
| LAN 内の探索 | 推定 | ルーターを経由しない通信（同じ Wi-Fi、同じスイッチ） | E1-2：ラベルのない実際のスキャンを検出 |
| ARP スプーフィング | 観測 | 被害機器の ARP が見えない位置でのキャプチャ | E1-3：27/27 を検出 |
| DoS への加担、フラッド | 推定 | なし | 検出器なし（E1-3 で 135 窓が未評価） |
| マルウェアへの感染そのもの | 不可（兆候からの推定まで） | — | 「感染の疑い」とだけ表現する |
| 通信の中身（暗号化された通信の内容、PII） | 不可 | TLS で暗号化されている場合 | 機器レポートの visibility limits に明示 |
| Bluetooth、Zigbee など IP 以外の通信 | 不可 | — | 対象外として明示 |

今後、この表の各行を、実測（公開データと実機）による根拠で裏づけていく。

## 5. 評価計画

| 評価 | データ | 指標 |
|---|---|---|
| 検出（条件単位） | 合成シナリオ、IoT-23、UNSW 攻撃データ、実機テストベッド | 条件ごとの再現率。見逃しの原因を「検出器がない／原理的に見えない／検出器の不足」に分類する |
| 適合率 | UNSW 正常データ（ホールドアウト）。検出結果を人が確認した結果を正解とする | イベントの種類別の適合率。根拠の種類別の適合率 |
| 既存ツールとの比較 | 上と同じデータ | 同じ正解ラベルに対する、Zeek と Suricata の検出範囲との差分 |
| 相関 | 上と同じデータ | イベント数から状況数への圧縮率。圧縮した後の再現率 |
| 時系列 | UNSW の 20 日分の連続データ | 変化検出の誤検知率。意図的に作った変化（実機）の検出率 |
| 資源 | すべて | 処理時間、最大メモリ。Raspberry Pi 5 での実測（実機の購入後） |

**原則**

- しきい値は開発用データで決め、ホールドアウトで評価する（D11）。
- 合成データは回帰の確認にだけ使う。

## 6. スコープ

- **対象**：自分が管理する家庭用ネットワーク上の IP 機器で、ゲートウェイからパッシブに観測できる通信。
- **対象外**：
  - 能動的な検査（スキャン、認証の試行）
  - TLS の復号
  - 機器内部の解析（ファームウェアの抽出など）
  - 他人のネットワーク

  能動的な検査が必要な比較は、別の実験として明示的に区別する。

## 7. 倫理とデータの取り扱い

- 実機での実験は、自分が所有する機器と、自分が管理するネットワークに限る。
- 公開データセットは各規約に従う（[DATASETS.md](DATASETS.md)）。データはリポジトリに含めない。
- 公開データの中に人名の入ったホスト名などが含まれていても、論文や資料には載せない。
