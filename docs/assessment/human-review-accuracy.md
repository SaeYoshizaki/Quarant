# 人による確認：違反の証拠としての判定（精度を上げる手順 4）

E4〜E12 で、Claude が「違反の証拠になる／ならない」と判定したものから 37 件を選んだ。判定が分かれそうなものを多めにしている。**Claude の判定はこのシートに書いていない**（判定のあとで突き合わせ、一致率を出す）。

## 判定のしかた

各項目について、「この観測された事実は、その要件の**違反の証拠**になるか」を、次の 3 つから選んでください。

- **○**：違反の証拠になる
- **×**：違反の証拠にならない（規格上は問題ない、または別の現象）
- **？**：通信からは判断できない（違反かもしれないが、確かめようがない）

値（パスワードなど）は、どの項目でも確認していません。キー名、方式名、ポート、向きだけから判断しています。

返答は、チャットに `1:○ 2:× 3:？ …` の形で書いてもらえれば十分です。迷った項目には、ひとことメモをもらえると助かります。

## 要件の要約（ETSI EN 303 645）

| 要件 | 内容 |
|---|---|
| 5.1-5 | 認証の仕組みは、総当たりの攻撃を実行しにくくする（遅延、締め出しなど） |
| 5.5-1 | 機器は、ベストプラクティスの暗号で通信する（TLS 1.0／1.1 は非推奨） |
| 5.5-4 | ネットワークから使える機器の機能には、認証を必要とする（制限されたネットワーク内で認証なしで提供するサービスは例外） |
| 5.5-6 | 重要なセキュリティパラメータ（パスワード、鍵、トークンなど）は、通信中に暗号化する |
| 5.5-7 | 遠隔から到達できるインターフェースで、重要なセキュリティパラメータを守る |
| 5.6-2 | 認証なしで、不要な情報（セキュリティに関わるソフトウェアのバージョンなど）を公開しない |
| 5.8-1 | 機器と関連するサービスの間の個人データは、暗号で守る |
| 5.9-3 | ネットワークへの再接続は、秩序立って行う（再試行の嵐を起こさない） |
| 5.12-1 | 初期設定が安全である |
