# 人による確認：違反の証拠として数える基準（精度を上げる手順 4）

E4〜E12 の数字は、個々の通信の判定ではなく、その裏にある**基準**で決まっている（「要求ごとの署名は秘密に数えない」など）。そこで、Claude が使った基準を一般化した形で並べ（36 件）、それぞれが要件の違反の証拠になるかを判定してもらう。各基準に、全データで何台の IoT 機器に効くかを添えた。

**Claude の判定はこのシートに書いていない**。判定のあとで突き合わせ、一致率と食い違いを記録する。基準が決まったら、各基準に当てはめた通信を無作為に抜き取り、当てはめの正しさを別に確かめる。

## 判定のしかた

各基準について、「この形の観測は、その要件の**違反の証拠**として数えてよいか」を、次の 3 つから選んでください。

- **○**：数えてよい
- **×**：数えない（規格上は問題ない、または別の現象）
- **？**：通信からは判断できない（候補として扱う）

返答は、チャットに `T1:○ T2:× …` の形で書いてもらえれば十分です。迷った基準には、ひとことメモをもらえると助かります。

## 要件の要約（ETSI EN 303 645）

| 要件 | 内容 |
|---|---|
| 5.1-3 | 機器の認証に使う暗号は、ベストプラクティスに従う |
| 5.1-5 | 認証の仕組みは、総当たりの攻撃を実行しにくくする（遅延、締め出しなど） |
| 5.3-7 | ソフトウェアの更新の仕組みには、ベストプラクティスの暗号を使う |
| 5.5-1 | 機器は、ベストプラクティスの暗号で通信する（TLS 1.0／1.1 は非推奨） |
| 5.5-4 | ネットワークから使える機器の機能には、認証を必要とする（制限されたネットワーク内で認証なしで提供するサービスは例外。例：DLNA） |
| 5.5-6 | 重要なセキュリティパラメータ（パスワード、鍵、トークンなど）は、通信中に暗号化する |
| 5.5-7 | 遠隔から到達できるインターフェースで、重要なセキュリティパラメータを守る |
| 5.6-2 | 認証なしで、不要な情報（セキュリティに関わるソフトウェアのバージョンなど）を公開しない |
| 5.8-1 | 機器と関連するサービスの間の個人データは、暗号で守る |
| 5.9-3 | ネットワークへの再接続は、秩序立って行う（再試行の嵐を起こさない） |
| 5.12-1 | 初期設定が安全である |
