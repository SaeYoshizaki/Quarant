# 24 件の調べ直し（2026-11-23）

[judge-2026-11-23.md](../judge-2026-11-23.md) の 24 件を、利用者から受け取った調査の手順（下の「決まり」）でやり直した。外付けディスクがないので、公開のデータセットを Mac に取り直し、機器ごとに切り出して調べた。

## 決まり（利用者の指示による）

- 目的は、データから観測できる事実と、収録の時点で製造者が説明していたことの**食い違い**を探すこと。セキュリティの良し悪しの評価や、脆弱性の診断ではない。
- 判定は 6 つ：**明確な矛盾**、**条件付きの矛盾**、**公式文書に記載なし**、**一致**、**観測不能**、**判断不能**。
- 文書は収録の時点までに公開され、そのとき有効だったものを使う。後の文書は参考として分け、当時も同じだったとは推定しない。
- **文書の表現があいまいなときは、最も限定的な読み方をとり、広げて読まない。**「弱い暗号」「一般に安全でない」といった評価だけでは食い違いにしない。
- 結論には、データ側（ファイル、時刻、相手、プロトコル、フィールド）と文書側（文書名、発行元、日付、URL、節、短い引用）の両方の証拠を付ける。片方しかなければ矛盾と言わない。
- 観測と解釈を分け、推測には「推測」と書く。

**区分の使い分け（この調べ直しでそろえたこと）**

- 「条件付きの矛盾」は、**データや文書からは決められない事実**が条件になる場合だけに使う（例：画像の送り先の持ち主、機器のファームウェアの版、データセットの操作が何だったか）。
- 文の**読み方**だけで矛盾かどうかが変わる場合は、最も限定的な読み方をとる。その読み方で矛盾しなければ「公式文書に記載なし」（または「一致」）にし、広く読めば矛盾になることを補足に書く。
- 「state-of-the-art」「industry-standard」「bank-level」のように、方法を書かない評価の言葉だけの約束は「判断不能」にする。

**前回（judge-2026-11-23.md）から大きく変わった点**

- 最も限定的な読み方をとったので、多くの「食い違いの候補」が「公式文書に記載なし」になった（Hue、Withings、Wink、TP-Link、HomePod、Awair、iRobot、Somfy、D-Link、Triby、VeraLite など）。通信の問題そのもの（平文、鍵の平文、偽の証明書の受け入れ）は残っている。
- Canary は「文言の上だけ」から「明確な矛盾」になった。文書が「すべての通信」と言い切っていて、平文の要求の相手が Canary 自身のサーバーだったため（中身は時刻合わせだけ）。
- SmartCam は、比べる文書を仕様の行から Hanwha 自身の脆弱性の報告に替えて、「条件付きの矛盾」にした。
- 新しく見つけたこと：VeraLite のログの中の Wi-Fi の設定とファームウェアの版、Withings Home の平文の証明書の取得、August の検査の直後の平文への切り替え、Triby の平文の通話、SmartCam の 40000 番への外からの接続、Govee の平文の通知、Canary の時刻合わせの仕組み。

## 断定できる範囲／できない範囲（全体）

- **断定できる**：各報告の「PCAP で観測された事実」は、取り直したデータで tshark で確かめたもの（「前回の記録」と書いたものを除く）。根拠は元のファイル名と時刻で示した。
- **断定できない**：
  - 暗号化された中身（TLS、DTLS、SRTP の中）。証明書の検証の実装（中間者の検査の結果は、データセットの作成者の能動的な検査を読んだもの）。保存時の暗号化。
  - 多くの製品で、ファームウェアの版が分からない（分かったのは Sonos、VeraLite、Triby、Govee、HomePod、Hue、TP-Link HS105 の取得した版）。版が条件になる判定（SmartCam）は「条件付き」にとどめた。
  - 文書が収録の時点で有効だったか（保存の日付は、公開の日付ではない）。後の文書は参考に分けた。
  - CIC IoT 2022、UNSW-IoTraffic、IoT-23 の分は、2026-11-23 には前回の記録で判定し、2026-11-26 に外付けディスクで確かめ直した（結果は同じ）。
- **プロンプトの決まりによる限界**：最も限定的な読み方をとったため、普通の読み手が受ける印象（例：「using SSL」はブリッジの通信全体のこと）と食い違う通信も「公式文書に記載なし」になっている。各報告の「補足」に、広く読めば矛盾になることを書いた。
