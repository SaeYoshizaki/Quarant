# 製造者の主張と通信の突き合わせ方（たたき台）

2026-10-31。[pilot-yourthings.md](pilot-yourthings.md) の 5 製品で出てきた形をもとにした。YourThings の残りに広げる前に決める。

## 1. 集める文書

製品ごとに、次の順で探す。

| 記号 | 文書 | 備考 |
|---|---|---|
| D1 | 製品ページ | 仕様の欄（「Encryption: Bank-Grade」など）も含む |
| D2 | セキュリティのページ、ホワイトペーパー、トラストセンター | 製造者全体のものでよい |
| D3 | プライバシーポリシー | セキュリティの節だけを主に使う。プライバシーの主張は補助として記録する |
| D4 | サポート・FAQ のセキュリティの記事 | サイト内で security、encrypt を探す |
| D5 | マニュアル、クイックスタート、データシート（PDF を含む） | アーカイブにあれば |
| D6 | ファームウェアのリリースノート | 2026-10-31 に追加 |

- **すべての製品で D1〜D6 を探す**（2026-10-31、D33）。製品ごと・文書ごとに、見つかったか、アーカイブにないか、アーカイブにはあるが読めないか（JavaScript で表示するページ）を [coverage.tsv](coverage.tsv) に残す。「主張がない」と言えるのは、探した範囲についてだけ。
- **製造者が自分で公開した文書だけを使う**（製造者のドメイン、製造者が置いた PDF）。第三者のサイト（manualslib など）や FCC の届出の書類は使わない。
- **読み落としの確認**：保存した全文書から、セキュリティの言葉を含む文を機械的に取り出し、主張の表にない文を 1 つずつ確かめる（`scripts/claims/sweep.py`）。
- **時期**：Wayback Machine で、キャプチャの最終日より前のいちばん近い版を使う。前の版がなければ、後のいちばん近い版を使い、「キャプチャ後」と記録する（根拠として弱い）。古い版も除かずに記録し、ずれは月数で残す（6 の `offset_months`）。
- 見ないもの：アプリストアの説明、報道、第三者のレビュー。
- 文書が見つからないことも記録する（「D2 なし」）。主張の有無を数えるため。

## 2. 主張の書き方の分類

| 分類 | 決め方 | 例（試し） |
|---|---|---|
| 具体的 | プロトコル（TLS、HTTPS）、アルゴリズムと鍵長（AES-128、RSA-2048）、性質（前方秘匿性、エンドツーエンド）、範囲（「すべてのデータ」「機器とクラウドの間」）、手順（署名つきの更新）のどれかを書いている | Nest、Canary |
| 曖昧 | 評価の言葉だけで、中身を書いていない（bank-grade、military-grade、best practice、secure） | Ring、Hue |
| 保証しない | 安全を保証しないと書いている | Belkin のプライバシーポリシー |
| なし | 集めた文書に、セキュリティの主張がない | Belkin NetCam HD の製品ページ |

1 つの文の中に具体的な部分と曖昧な部分があれば、具体的な部分だけを判定に使う。

曖昧な主張でも、何について言っているかが分かるもの（「Encryption: Bank-Grade」は暗号化について言っている）は、その最低限の中身（「暗号化している」）だけを T1 として判定する。評価の言葉（bank-grade）は判定に使わない。何について言っているかも分からないもの（「best practice security features」）は判定しない。

## 3. 主張の型と、食い違いの条件

通信から判定できるのは、主張が具体的で、下の「食い違いの条件」が通信に現れうるものだけ。ETSI の要件は、TS 103 701 の分類（[assessment/ts103701-final.md](../assessment/ts103701-final.md)）で、通信の観測者が不合格だけ示せるとしたもの。

| 型 | 主張の例 | 食い違いの条件（通信で見えるもの） | 一致とするもの | 見る記録 | ETSI |
|---|---|---|---|---|---|
| T1 通信の暗号化（範囲） | 「すべてのデータを暗号化」「機器からクラウドまで HTTPS」 | 主張の範囲の通信が平文。**T1a**：本文、パラメータ、認証情報、映像のどれかを含む。**T1b**：中身のない要求だけ（HEAD、接続確認） | 範囲の通信がすべて TLS | Zeek http・tls、Quarant `INSECURE_*` | 5.5-1、5.8-1 |
| T2 暗号の性質 | 「AES-256」「前方秘匿性」「TLS 1.2 以上」「RSA-2048」 | 選ばれた暗号スイート・版・証明書の鍵長が、書かれた性質を満たさない | 見えた握手がすべて満たす | Zeek tls（ServerHello）。証明書は TLS 1.2 以下だけ見える | 5.5-1 |
| T3 認証情報の保護 | 「パスワードは暗号化して送る」「平文で送らない」 | 平文の通信に Authorization、password などのフィールドがある | 見えない | Quarant `INSECURE_HTTP_AUTH` など、Zeek http のヘッダー名 | 5.5-7 |
| T4 映像・音声の保護 | 「映像は暗号化して送る」 | 平文の JPEG、RTSP／RTP が外へ出る | 見えない | Quarant 5.8-1 の検出、Zeek | 5.8-1、5.8-2 |
| T5 更新 | 「更新は安全に配信」「暗号化して配信」 | 更新の取得が平文。**ただし「署名つき」だけの主張には食い違わない**（平文でも署名は検証できる） | 取得が TLS | Quarant `I4_FIRMWARE_UPDATE_OBSERVED`、Zeek http の宛先 | 5.3-7 |

### 通信では判定できない主張

次の主張は、通信を見ても確かめられない。「判定できない」として数え、理由を付ける。

| 主張 | 理由 |
|---|---|
| 証明書を検証している | 検証するかどうかは、偽の証明書を出さないと分からない（能動的な検査） |
| 保存時の暗号化、パスワードのハッシュ化、VPC、社内の権限 | クラウドの内部のこと |
| 第三者の監査、自動更新をしている、定期的に更新する | 3 日のキャプチャでは、ないことを示せない |
| 署名つきの更新 | 署名は暗号化された中身か、ファームウェアの中にある |

文書だけで確かめられるもの（脆弱性の届け出の窓口 5.2-1、サポート期間 5.3-13）は、通信とは別に記録する。

## 4. 判定

主張 1 つにつき、次のどれか 1 つを付ける。

- **食い違いの候補**：T1a〜T5 の条件に当たる通信がある。人が確かめるまで「候補」のまま。
- **文言の上で食い違い**：T1b（中身のない平文だけ）。
- **一致（見えた範囲で）**：条件に当たる通信がなく、主張の性質が通信で確かめられた（T1、T2）。
- **見えない**：条件に当たる通信がない。ただし主張を確かめる手段もない（T3〜T5）。安全の証明としない。
- **判定できない**：曖昧、保証しない、または上の「通信では判定できない主張」。

数える単位は、主張と製品の両方。機器が複数台あっても製品 1 つとする。

## 5. 決めたこと（2026-10-31、D32）

- **数える単位は製品**。製造者の共通のページ（D2、D3）を複数の製品が使うときも、製品ごとに 1 行ずつ書き、`shared_source` を `yes` にする。製造者ごとに数え直すときはこの列で重複を除く。
- **観測の範囲は、パッシブに見える通信すべて**（外部への通信も LAN 内も）。観測した範囲を `obs_scope`、主張が言っている範囲を `claim_scope` に書く。主張が範囲を限っていて（「機器とクラウドの間」）、食い違う観測がその範囲の外（LAN 内）だけのときは、判定のメモにそう書く。数えるときに絞れるよう、観測は捨てない。
- **キャプチャからのずれは、今は除外しない**。`offset_days` と `offset_months` に入れ、あとで「何か月以上ずれたものを除く」ができるようにする（下の 6）。

## 6. 記録

主張 1 つにつき 1 行（[claims.tsv](claims.tsv)）。

| 列 | 中身 |
|---|---|
| dataset | データセット（[devices.tsv](devices.tsv) と同じ記号） |
| product | 製品の名前 |
| catalog_product | [devices.json](devices.json) の「製造者 製品」。キャプチャの期間を引くのに使う |
| doc | D1〜D5 |
| url | アーカイブの URL |
| snapshot | アーカイブの日付 |
| timing | before／during／after（キャプチャの期間との関係。スクリプトが付ける） |
| shared_source | 製造者の共通のページなら yes |
| quote | 引用（原文のまま） |
| type | T1〜T5、none、not assessable |
| specificity | specific／vague／disclaimer／none |
| claim_scope | 主張の範囲（device-cloud、app-cloud、lan、all、cloud） |
| obs_scope | 観測の範囲（external、lan、external+lan） |
| judgment | 4 の判定 |
| evidence | 根拠（件数と、どの記録か） |
| note | メモ |
| capture_start、capture_end | その製品がそのデータセットで見えた期間（スクリプトが付ける） |
| offset_days、offset_months | アーカイブの日付とキャプチャの期間のずれ。前ならマイナス（キャプチャの初日から何日前か）、後ならプラス（最終日から何日後か）、期間中は 0（スクリプトが付ける） |

`timing` と `capture_*`、`offset_*` は手で書かず、`python3 scripts/claims/claim_offsets.py docs/claims/claims.tsv docs/claims/devices.json` で付ける。

文書に認証情報の値（初期パスワードなど）が書かれていても、引用では値を `***` に置き換える（`check_quotes.py` は `***` を任意の値として照合する）。

引用が原文どおりかは、利用者が抜き取りで確かめる（取得した版は `~/datasets/claims/snapshots/` に保存してある）。

## 決めていないこと

- 「キャプチャ後」や古い文書を、何か月で除くか（列はあるので、あとで決める）。
