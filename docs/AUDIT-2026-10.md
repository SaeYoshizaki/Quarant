# 既存実装の調査結果（2026-10-16）

Phase 1 着手前に、`main`（commit `ac87051`）のコードを読んで確認した事実をまとめる。
README の記述ではなく、コードと実行結果を根拠にしている。確認できなかったことは「不明」と書く。

## 1. 規模と構成

- Go 約 4 万行。外部依存は `github.com/google/gopacket` のみ。Web UI は Next.js（`web/`）。
- ローカルと `origin/main` に差分はなかった。未コミット変更もなかった。
- 調査時点で `go build`、`go vet`、`go test ./...` はすべて成功していた。

| ディレクトリ | 役割 |
|---|---|
| `analyzer/` | PCAP／ライブキャプチャの解析エンジン。`engine.go`（パケット読み込み）、`flow.go`（中核ハンドラ、約1100行）、`cache.go`（TCP フロー状態）、`observation.go`、`notifications.go`（I8 通知）、`risk_layer.go`、`user_guidance.go` |

| `internal/viewer/` | ローカル HTTP API と静的 UI の配信 |
| `cmd/quarant-api`, `cmd/quarant-agg` | 旧ツール。どこからも参照されていない |
| `web/` | Next.js UI。`page.tsx` 1 ファイルで約 3900 行。`web/out` は未ビルド |
| `examples/`, `evaluation/docker-openwrt-lab/` | OpenWrt／IDS ログのフィクスチャ。Docker lab は固定ログを書き出すだけで、OpenWrt もトラフィックも含まない |

## 2. データの流れ

```text
PCAP / interface ──> analyzer.Engine ──> FlowHandler（TCP は16KB までペイロードを蓄積）
                                          ├─ rules.Run(ctx)       -> events.jsonl
                                          ├─ flow snapshots       -> flows.jsonl
                                          ├─ observations         -> observations.jsonl
                                          └─ device.Store         -> device_inventory.json
OpenWrt / Suricata / Zeek / Snort ログ ──> cmd/quarant/*.go 取り込み -> security_events.jsonl ほか
                                          └─> evidence assemble -> precision -> mitigate -> eval -> research report
```

## 3. 実装済みの機能（コードで確認）

- **PCAP 解析**：オフライン（ファイル、標準入力）とライブ（`pcap.OpenLive`）。
- **プロトコル解析**：HTTP リクエスト、MQTT CONNECT/PUBLISH、Telnet のプロンプト、TLS の ClientHello、ServerHello、TLS 1.2 以下の証明書、JA3。DNS クエリは観測レコードとして記録する。
- **平文認証情報の検出**：HTTP の Basic 認証、Cookie、トークン、ボディ、MQTT のパスワード、Telnet のログイン。出力時は `***` でマスクする。
- **TLS のリスク判定**：古いバージョン、弱い暗号スイート、証明書の異常（自己署名、期限切れ、SNI 不一致）。
- **知識ベースとの照合（I3〜I6）**：ベンダーやファミリーの推定、I5 の脆弱性候補、EOL、プライバシー方針との照合。
- **イベントの説明フィールド**：`observed_fact`、`inference`、`limitation`、`confidence`、`recommendation`。
- **外部ログの取り込み**：OpenWrt（firewall、dnsmasq、DHCP lease、conntrack）、Suricata EVE、Zeek TSV、Snort。共通形式 `security_events.jsonl` に変換し、psad 風の scan／sweep 集約もある。
- **研究用パイプライン**：インシデント化、OpenWrt 向け緩和スクリプトの生成（dry-run が既定で、ルーターへは送信しない）、before/after 評価、quality gate、研究レポート（Markdown、CSV、LaTeX、SVG）。

## 4. 不具合と設計上の問題（調査時点）

### 解析の中核（`analyzer/`）

1. **時刻**：オフライン解析で、パケットの記録時刻ではなく `time.Now()` を使っていた（`flow.go` の `HandlePacket`）。5 月の PCAP を解析しても、イベントは解析した日時になった。時系列比較ができず、結果も再現しない。
2. **外部 IP の端末化**：外部サーバーの IP まで端末として登録していた。実 PCAP では 68 台登録され、ほぼすべてがインターネット上のサーバーだった。その結果 `I8_NEW_DEVICE_OBSERVED` が誤って大量に出た。
3. **フローの最終値の欠落**：入力の終わりに未出力のフローを書き出す処理がなかった。そのため各フローの最終的なパケット数やバイト数が失われた。実 PCAP では 100 フローに対して 2941 行のスナップショットが出ていた。
4. **知識ベースの読み込み**：カレントディレクトリからの相対パスで読んでいた。リポジトリの外で実行すると起動に失敗し、しかも出力ファイルを空にしてから失敗していた。
5. **帰属の誤り**：サーバー側の問題を、接続した側の端末に帰属させていた。例えば、カメラの Telnet や管理画面の問題がスマートフォンの問題として記録された。
6. **未応答 SYN の扱い**：応答のない SYN だけで「Telnet サービス観測」と判定していた。スキャンが誤って分類された。
7. **管理画面の誤判定**：ホスト名の部分一致（`cam`、`dvr`）や Authorization ヘッダがあるだけで「管理画面」と判定していた。
8. **認証情報の誤検知**：
   - `Sec-WebSocket-Key` を CRITICAL の認証情報露出として扱っていた。
   - MQTT のトピック名に `token` などの語が含まれるだけで CRITICAL にしていた。
9. **TLS 暗号の判定**：
   - クライアントが CBC スイートを提示するだけで警告していた。最新の TLS 実装はほぼすべて CBC を提示する。
   - 暗号名の表が 30 件しかなく、GCM などの最新スイートを「最新」と判定できなかった。
10. **脆弱性候補の重大度**：適用可否が未確認の I5 照合（確信度 low）を CRITICAL にしていた。
11. **デバッグ出力の平文**：`--debug` を付けると、パケット先頭 256 バイトを平文のままログに書いていた。パスワードを含み得る。
12. **データ競合**：インベントリを書き出すゴルーチンが、解析中の map をロックなしで読んでいた。長い PCAP ではクラッシュし得た。
13. **端末識別の欠落**：MAC アドレス、DHCP、mDNS、SSDP からの識別がなかった。`tool/input/oui.csv` もコードから使われていなかった。
14. **振る舞い検知の欠落**：スキャンと周期通信を検出する仕組みがなかった。
15. **旧エントリポイント**：`-i` の既定値が `eth1` なので、`-pcap` を指定すると常にエラーになった。

### ローカル API（`internal/viewer`）

16. **CORS**：`Access-Control-Allow-Origin: *` を返していた。ブラウザで開いた任意の Web サイトから、ローカルの通信データを読める状態だった。Host ヘッダの検査もなく、DNS リバインディングにも弱かった。

### 外部ログの取り込み（`cmd/quarant`、実在形式のログで確認）

17. **OpenWrt logread の時刻**：`logread` 形式（`Sat Sep 26 12:00:02 2026 ...`）の時刻を解析できず、全イベントが `--now` の時刻になった。年をまたぐログも誤って解釈していた。
18. **Suricata の flow_id**：float64 として扱っていたため、桁あふれで別のフローと衝突した。
19. **Snort 3 の JSON**：時刻、`class`、文字列で書かれたポートを解析できず、アラートを丸ごと落としていた。
20. **nf_conntrack**：`/proc/net/nf_conntrack` 形式でプロトコルを `ipv4` と誤認していた。64KB を超える行で取り込み全体が止まった。
21. **DHCP lease**：lease の失効時刻を、端末を観測した時刻として使っていた。
22. **端末一覧の欠落**：`evidence assemble` が `device_inventory.json` を引き継いでいなかった。
23. **ssh の引数**：`openwrt collect --host` に `-` で始まる値を渡すと、ssh のオプションとして解釈された。

### 保守性

- **巨大ファイル**：`precision.go`（1780 行）、`mitigation.go`（1657 行）、`page.tsx`（3887 行）。
- **重複実装**：JSONL の読み込みは同じ処理が約 15 箇所にある。
- **package main への集中**：取り込み処理がすべて package main にあり、ほかのパッケージから再利用できない。
- **独自スコア**：`precision` には加重スコア（例：score 92）がある。重みの根拠は文書化されていない。ユーザーの方針 6.4 と照らして見直しが必要（未着手）。
- **知識ベースの出典**：21 件中 14 件に出典や確認日がない。CVE-2023-1389（TP-Link Archer ルーターの脆弱性）が Kasa／Tapo 系の製品に紐づけられている。
- **リポジトリ直下の不要ファイル**：`event.json`、`wget-log`、`.codex`（いずれも空）、`events.old.jsonl`、`kari.json`、`report.json`、`tree.txt`、`package-lock.json`。`clab-*/` には containerlab の実行時状態が入っており、ホスト側のユーザー名を含むパスが記録されている。
- **Web UI**：`next.config.mjs` に `ignoreBuildErrors: true` が設定されている。`@vercel/analytics` が含まれている。

### テスト

- **カバレッジ**：rules 56%、device 64%、knowledge 12%、reportapi 76%、cmd 74%。
- **テストのない部分**：PCAP 経路のエンドツーエンド、`ParseHTTP`、`DetectTLSClientHello`、viewer。
- **実データでの確認**：実 PCAP や、実在形式のログを使ったテストはなかった。
